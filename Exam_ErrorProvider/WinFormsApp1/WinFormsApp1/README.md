# 배송지 입력 폼 - 입력 검증과 메시지 처리 (WinForms)

배송지를 입력하는 작은 폼을 만들면서 WinForms의 입력 검증 방식(`ErrorProvider`, `Validating`)과
사용자 메시지 처리를 익힌 실습입니다.

## 이번 과제의 목적

- Delphi에서는 `OnExit` 안에서 `ShowMessage`로 처리하던 입력 검사를, WinForms의 방식으로 옮겨 보기
- 오류를 팝업 대신 **입력칸 옆 아이콘**(`ErrorProvider`)으로 보여 주는 흐름 이해하기
- 검증 규칙을 화면 코드에서 분리하기
- 메시지창 호출과 폼 닫기 확인을 한곳에서 일관되게 다루기

기능을 익히는 게 목적이라 **일부 입력칸(받는 사람, 휴대폰, 배송일, 결제 수단/입금자명)만 검증**했습니다.
실무라면 우편번호·주소 등 모든 칸을 검증하고, 버튼 활성화 조건(`IsFormValid`)에도 넣어야 합니다.
전역 예외 처리(`Application.ThreadException`)는 이번에는 하지 않았습니다.

## 화면과 구성

| 입력 | 규칙 |
|---|---|
| 받는 사람 | 2~20자 |
| 휴대폰 | `010-1234-5678` 형식 (정규식) |
| 희망 배송일 | 오늘부터 30일 이내 |
| 결제 수단 / 입금자명 | 무통장일 때만 입금자명 필수, 카드면 입력칸 비활성화 |

| 파일 | 역할 |
|---|---|
| `Form1.cs` | 이벤트 처리, 오류 표시, 버튼 동작 |
| `Validator.cs` | 검증 규칙. 오류 문구를 돌려주고, 통과하면 `null` |
| `MessageService.cs` | `MessageBox` 호출을 모은 정적 클래스 (안내/경고/오류/확인) |

## 익힌 것

- **`ErrorProvider`**: `SetError(컨트롤, 문구)`로 표시하고 `SetError(컨트롤, "")`로 지운다.
- **`Validating` 이벤트**: 포커스를 잃을 때 호출된다. `e.Cancel = true`면 다른 칸으로 이동하지 못한다.
  오류 표시(`SetError`)와 이동 차단(`e.Cancel`)은 항상 같이 해야 한다.
- **`ValidateChildren()`**: 폼이 이미 가진 메서드. 모든 입력칸의 `Validating`을 한꺼번에 호출하고,
  하나라도 실패하면 `false`를 돌려준다. 신청 버튼에서 최종 점검할 때 쓴다.
- **검증 로직 분리**: 규칙은 `Validator`에서 "오류 문구 또는 null"로 돌려주고, 폼은 그 결과를 화면에 반영만 한다.
  정규식은 `static readonly`로 한 번만 만든다.
- **연관된 규칙**: 결제 수단에 따라 입금자명의 필수 여부가 달라진다.
  `Validating`은 해당 칸이 포커스를 잃을 때만 호출되므로, 결제 수단이 바뀔 때 직접 다시 검사해야 한다.
- **표시와 판단의 분리**: `Validating`은 오류를 화면에 띄우고, `IsFormValid()`는 화면을 건드리지 않고 통과 여부만 계산한다.
  `IsFormValid()`로 신청 버튼의 활성/비활성을 정한다.
- **입력 중 피드백**: `TextChanged` 등으로 이미 뜬 오류는 지우되, 새 오류는 칸을 벗어날 때만 띄운다.
  서로 다른 이벤트(`TextChanged`, `ValueChanged`, `SelectedIndexChanged`)도 시그니처가 같아 핸들러 하나로 묶을 수 있다.
- **메시지 통일**: `MessageService`로 제목과 아이콘을 맞추고, 닫을 때(`FormClosing`) 입력한 내용이 있으면 확인을 받는다.
  신청 처리는 `try/catch`로 사용자용 문구만 보여 주고 상세 내용은 `Debug.WriteLine`에 남긴다.

## 막혔던 곳과 해결

**1. "첫 번째 오류 칸"의 순서**
- 증상: 어떤 칸에 먼저 포커스를 줘야 할지 기준이 없었다.
- 원인: `ValidateChildren()`의 내부 호출 순서가 화면 순서와 같다는 보장이 없다.
- 해결: 화면 순서대로 컨트롤 배열을 직접 만들고, 그 배열에서 오류가 남은 첫 칸을 고른다.
  메시지를 먼저 닫은 뒤 `Focus()`를 줘야 포커스가 원래 위치로 돌아가지 않는다.

**2. 결제 수단을 바꿔도 입금자명 오류가 그대로**
- 증상: 무통장에서 카드로 바꿨는데 입금자명 칸의 오류 아이콘이 남았다.
- 원인: 입금자명 칸에는 포커스가 없어서 `Validating`이 호출되지 않는다.
- 해결: 결제 수단의 `SelectedIndexChanged`에서 입금자명 칸의 활성 상태와 오류 표시를 직접 정리한다.

## 정리

화면 코드는 "언제 검사하고 무엇을 보여 줄지"만 맡고, "무엇이 올바른 값인지"는 `Validator`가 맡는 구조로 나누는 것이 핵심이었습니다.
같은 규칙을 `Validating`(표시용)과 `IsFormValid`(버튼 상태용)가 함께 쓰기 때문에 이 분리가 실제로 도움이 됐습니다.
